# v0.3.0 balance and existing-wallet opening

Engineering plan: [task 18](../plans/18-balance-and-existing-open.md).
Bark remains bfbe6b7c3088a09dd4e81c4ac24cdc763a627a8c; BoltFFI remains 0.31.1.

## Implementation

`Balance` retains its six prior fields and exposes `needsRefreshSats`,
`pendingArkoorSendSats`, `pendingOffboardSats`, `pendingSats` and `totalSats`.
The aggregates call Bark's methods. No wallet classification or transaction
validation was changed. The checked inventory now includes 150 exports and all
11 balance fields in both generated host languages.

`OnchainWallet.openExisting` and creation-disabled `Wallet.open` share a
read-only identity check before Bark's SQLite migrations/BDK writes. Creation
factories retain their previous behavior. The check uses Bark's seed parser and
fingerprint, validates the stored network and requires initialized properties.
Compatibility filenames and schema 42 remain supported. SQLite URI metacharacters
are encoded; a live WAL's committed identity is checked rather than ignoring it.
Preflight cannot create a WAL index or recover a hot journal. Such inputs fail
without recovery; closed WAL-mode databases open without creating sidecars.

## Regression and acceptance

The original onchain factory reproduced the empty-file corruption: an empty
`db.sqlite` acquired Bark/BDK tables before returning. The replacement contract
calls the new existing-only factory. Rust, Swift and Kotlin test missing/empty/
foreign databases, wrong network and wrong mnemonic; each compares input bytes
and complete directory contents after both rejected opening paths. Byte equality
also proves no tables were added. Positive contracts copy the public schema-42
fixture and actually open onchain and Bark handles against Bitcoin RegTest.

The live balance contracts fund new temporary wallets and run real boards, Ark
sends and offboards. A transparent local TCP proxy adds 250ms server-response
latency; it forwards the real protocol unchanged so pending input locks can be
sampled. No checkpoint, balance or transaction is mocked. Tests verify the full
input amount including change remains counted while operations are in flight,
then complete the operations. Mining beyond the recipient VTXO's expiry verifies
10,000 sats move from spendable to needs-refresh while remaining in total.
Rust additionally compares funded FFI aggregates directly with Bark and tests all
nine buckets with distinct values. Live Rust cases run sequentially because
expiry mining must not age another test's wallet.
