## Implementation

`Balance` retains its six prior fields and exposes `needsRefreshSats`,
`pendingArkoorSendSats`, `pendingOffboardSats`, `pendingSats` and `totalSats`.
The aggregates call Bark's methods. No wallet classification or transaction
validation was changed. The checked inventory now includes 150 exports and all
11 balance fields in both generated host languages.

`OnchainWallet.openExisting` and creation-disabled `Wallet.open` share a
read-only identity check before Bark's SQLite migrations/BDK writes. Creation
factories retain their previous behavior. The check uses Bark's seed parser and
fingerprint, validates the stored network and requires initialized properties.
Compatibility filenames and schema 42 remain supported. SQLite URI metacharacters
are encoded; a live WAL's committed identity is checked rather than ignoring it.
Preflight cannot create a WAL index or recover a hot journal. Such inputs fail
without recovery; closed WAL-mode databases open without creating sidecars.
Rollback-mode databases use ordinary read-only SQLite, preserving valid PERSIST
wallets whose completed commits leave a zeroed journal file.

## Regression and acceptance

The original onchain factory reproduced the empty-file corruption: an empty
`db.sqlite` acquired Bark/BDK tables before returning. The replacement contract
calls the new existing-only factory. Rust, Swift and Kotlin test missing/empty/
foreign databases, wrong network and wrong mnemonic; each compares input bytes
and complete directory contents after both rejected opening paths. Byte equality
also proves no tables were added. Positive contracts copy the public schema-42
fixture and actually open onchain and Bark handles against Bitcoin RegTest.

The live balance contracts fund new temporary wallets and run real boards, Ark
sends and offboards. A transparent local TCP proxy adds 250ms server-response
latency; it forwards the real protocol unchanged so pending input locks can be
sampled. No checkpoint, balance or transaction is mocked. Tests verify the full
input amount including change remains counted while operations are in flight,
then complete the operations. Mining beyond the recipient VTXO's expiry verifies
10,000 sats move from spendable to needs-refresh while remaining in total.
Rust additionally compares funded FFI aggregates directly with Bark and tests all
nine buckets with distinct values. Live Rust cases run sequentially because
expiry mining must not age another test's wallet.

## PERSIST compatibility correction

A new Rust regression reproduced rejection of a valid schema-42 wallet with a
cold PERSIST rollback journal. SQLite's ordinary read-only open now decides
whether rollback journals need recovery; immutable mode is restricted to closed
WAL databases, identified by the SQLite file header. This retains cold journals
unchanged and preserves the missing-WAL-index guard. The regression checks both
a successful identity validation and wrong-network rejection without byte or
directory changes. Final source rebuilds and local contracts passed as recorded above.

## Fable 5.1 high review and verified repairs

Round 1 reviewed the full diff from d059089, including the uncommitted PERSIST
correction, using Claude Fable 5.1 with effort high. It found no balance or
write-ordering defects, one should-fix error diagnosis and two suggestions.

- Hot journal: confirmed with the Rust-linked SQLite via a real transaction and
  `cache_flush`, then copied main/journal before rolling back the source. The
  misleading initialized-properties message reproduced. The actual extended
  rollback code is 776 (the review said 264); the fix uses SQLite's named
  READONLY_ROLLBACK and READONLY_RECOVERY constants. Missing properties retain
  their specific error, recovery errors request recovery, and other read errors
  retain their cause under a general read failure. Input bytes remain unchanged.
- Empty header: confirmed the bare `failed to fill whole buffer` error and added
  `empty or truncated` context. Both Swift/Kotlin rejection contracts assert it.
- Zero-length WAL: confirmed the old branch accepted a WAL without an index.
  Presence now selects ordinary read-only SQLite even for zero bytes; only an
  absent WAL selects immutable mode. A zero-length live WAL/index validates;
  missing-index inputs fail without creating files. Opening is serialized against
  external writers/replacement; no journaling overrides were found in Noah's
  active native rewrite checkout during inspection.

All three new targeted regressions failed before the fixes and all seven DB
contracts passed on the Rust-linked build (0.08s). Full local native checks,
SDK rebuilds and Fable verification subsequently passed.
