# Opus 5.5 migration review

Status: fixes and local SDK/app/paired RegTest checks pass; hosted validation pending.

Reviewed original d3c0f38 through 863326a using Claude Opus 5.5 (high effort).
The independent review found no material Rust wallet-logic, PSBT validation,
persistence or callback-ownership defect. Findings were independently checked
against callers, existing evidence, repository settings and platform docs before
implementation. [Engineering plan](../plans/15-opus-review-fixes.md).

## Focused cleanup

- One private async-dispatch helper replaces 96 repeated clone/offload pairs.
  An Arc shares the immutable core/recovery report rather than copying its ID
  vectors on each async call. No measured throughput claim is made.
- Remove the duplicate Bark handle, unused from_inner/dead-code suppression,
  obsolete onchain TODO and unused direct invoice/Tokio signal/fs requirements.
- Keep config()'s async public API, return its synchronous value without a Tokio hop.
- Do not change inherited panic handling or callback threading without a concrete
  failing case. No additional wallet reset/account-management feature was added.

## Regression evidence

Before fixes, `python3 -m unittest discover -s tests/python -v` reproduced stale
release verification, missing tag protection and ZIP mtime drift. All eight
release/runner cases now pass, including remote-unavailable fail-closed behavior.
The actual v0.1.0 tag also rejects staging before changing Package/provenance.
Normal integrity verification passes on the newer development source; strict
release-source verification correctly rejects the older published SDK snapshot.

Native seed retry tests failed on both real simulator/emulator processes before
the change. iOS also failed directory uniqueness/backup metadata assertions.
After the fix, all three iOS unit tests plus the UI test pass; Android seed/UI
tests, minified release build and lint pass. Test accounts are unique and removed;
no recovery phrases enter test output, and existing wallet accounts are untouched.

Rust: all57 tests and warnings-denied Clippy pass after Arc/dispatch cleanup.
Audit passes with no ignored advisories after removing direct unused dependencies.
Strict generation/API parity passes for both development SDKs. All three Swift
contracts and all three real-wallet JVM contracts pass, including through the
actual JAR. The final no-extra-async-state helper also passes all57 Rust tests
and warnings-denied Clippy.

The installed Android APK's compiled manifest includes allowBackup=false and
dataExtractionRules; its compiled XML excludes file/sharedpref domains for both
cloud backup and device transfer. iOS's directory exclusion flag is asserted by
the simulator unit test. This does not claim an actual cross-device transfer.

Final runtime checks also exposed two issues before pushing: a reused RegTest
chain's old tip kept LND unsynced for 120 seconds despite sufficient funds, and
the new async helper added enough debug stack use to crash iOS Wallet.sync at
Tokio spawn. Mining one block made the same LND report synced at height513.
The iOS crash reproduced twice with a single open/sync command. Removing only
the redundant helper async state made that same installed-app command pass;
the helper returns run_async's future directly, preserving lazy Tokio submission
and cancellation. Full acceptance subsequently passed against both updated SDKs.

An overbroad new history assertion failed on the post-exit restore. The distinct
new database contained one newly reconstructed bark.exit/start movement, created
by upstream sync_force_exited_vtxos during scanning, rather than reused history.
Empty history is therefore checked on the first funded restore before exits;
all restores still require distinct database IDs and complete recovery reports.

`app-regtest.py --extended --run-id opus55-review-20261019-r2` passed on iOS27
arm64 simulator and Android35 arm64 emulator with the rebuilt development SDKs.
Both apps passed two-way Ark transfers, settled BOLT11 payments/receives, refresh,
offboard, emergency fee estimates, unilateral exits/claims with confirmed chain
transactions, cancellation/reuse, invalid input and unavailable-server retry.
Each platform completed two restores into distinct UUID databases, with complete
recovery reports, matching fingerprints and funded Ark/onchain balances.
The paired hosted-workflow run and full hosted release ABI builds are pending.

## Source references and limits

The runner is trusted-code execution, not a sandbox. [GitHub runner access guidance](https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/manage-access).
Android's allowBackup flag alone does not cover every OEM device transfer path;
[Android12 backup changes](https://developer.android.com/about/versions/12/behavior-changes-12#backup-restore).
iOS exclusions use [URLResourceValues.isExcludedFromBackup](https://developer.apple.com/documentation/foundation/urlresourcevalues/isexcludedfrombackup).
Actual cross-device backup/transfer, physical/minimum-OS execution and external
LNURL/LNAddress/BOLT12 provider fixtures remain outside available runtime coverage.
No v0.1.0 release tag, binary asset or committed generated binding was replaced.
